# AI Memory 八周学习计划

## 目标与范围

本计划面向芯片技术预研工程师，目标是在有限时间内建立足以开展 AI Memory 预研的知识与实验基础。

- 前 2 周快速建立完整概念地图：LLM、Transformer、推理、KV Cache、Agent 与长期记忆。
- 后 6 周围绕数据结构、访问路径、性能指标和记忆生命周期逐步细化。
- 暂缓 RAG 的 chunking、稀疏/稠密检索、混合检索及重排对照；确有需要时再补。
- 每周投入 5–8 小时，其中平日以短时学习为主，周末集中安排 4–6 小时实验。
- 前两周建议尽量投入 7–8 小时。重点是建立可用的工程心智模型，不要求一开始就熟练推导全部公式。

学习每个机制时，持续回答四个问题：数据存在哪里、何时读写、搬运多少、是否处于关键路径。

## 八周路线

| 周次 | 学习重点 | 周末动手成果 | 完成标准 |
| --- | --- | --- | --- |
| 第 1 周 | LLM、token、embedding、Transformer、causal attention | 运行并修改单头因果 Attention 小实验 | 能说明 Q/K/V、因果掩码和主要中间矩阵的作用 |
| 第 2 周 | 逐 token 生成、prefill/decode、KV Cache、Agent 与长期记忆 | 运行逐 token 生成和 KV Cache 演示；画出 Agent memory 闭环 | 能区分 context、KV Cache、Agent state 和长期记忆 |
| 第 3 周 | Attention 与 KV Cache 细化 | 手写增量 Attention，并与完整重算对齐 | 能说明缓存带来的计算节省、容量占用和访问开销 |
| 第 4 周 | 推理性能与资源画像 | 改变输入长度、输出长度和 batch，记录时延与内存 | 能区分 TTFT、生成速度、吞吐、权重占用与 KV 占用 |
| 第 5 周 | Agent 执行机制 | 实现工具调用、状态更新和停止判断的最小 Agent | 能追踪一次任务的模型、工具和状态变化 |
| 第 6 周 | 长期记忆的数据模型 | 实现事实、事件、规则三类持久化记忆 | 重启程序后能够恢复记忆，并能追溯来源 |
| 第 7 周 | 记忆生命周期 | 实验更新、冲突、失效、遗忘、删除和权限 | 当前状态、历史状态和删除语义均有明确处理方式 |
| 第 8 周 | 性能画像与预研收敛 | 找出一个可测量的记忆瓶颈并形成软硬协同假设 | 交付现象、证据、候选机制与下一步实验方案 |

## 两周后的概念验收

两周后应能清楚回答：

1. LLM 如何把文本变成 token，并逐 token 生成？
2. embedding、Q/K/V 和 attention output 分别是什么？
3. Transformer 一层大致包含哪些模块？
4. prefill 和 decode 有什么区别？
5. KV Cache 缓存什么，容量为什么随序列长度增长？
6. context、KV Cache、Agent 短期状态和长期记忆有何区别？
7. Agent 的一次行动循环中，模型、工具、状态和记忆如何交互？
8. 从芯片角度看，哪些步骤可能受计算、容量或带宽限制？

## 第 1 周：Transformer 与 Attention

### 学习材料

按顺序使用以下材料。本周前两项必看，第三项用于实验时查图，第四项选看。

1. [3Blue1Brown：GPT 是什么？直观解释 Transformer](https://www.bilibili.com/video/BV13z421U7cs/)，约 27 分钟。
2. [3Blue1Brown：Attention in transformers, step-by-step](https://www.3blue1brown.com/lessons/attention/)，约 26 分钟，网页同时提供图文内容。
3. [Jay Alammar：The Illustrated GPT-2](https://jalammar.github.io/illustrated-gpt2/)，重点查看逐 token 生成和 masked self-attention 的图。
4. [Andrej Karpathy：Intro to Large Language Models](https://www.youtube.com/watch?v=zjkBMFhNj_g)，约 1 小时，作为总体认识的补充。

### 平日短时学习

#### 第一次学习：总体图景，约 45 分钟

观看第一项材料，记录下面的数据流：

`文本 → token → embedding → 多层 Transformer → 下一个 token 的概率 → 选出 token → 重复`

用自己的话回答：

- token 和词有什么区别？
- embedding 为什么使用向量？
- 为什么模型需要反复运行才能生成一段话？

#### 第二次学习：Attention，约 45–60 分钟

观看第二项材料，沿着以下路径追踪数据：

`X → Q/K/V → QKᵀ → causal mask → softmax → attention weights × V → output`

第一遍只需形成以下直觉：

- Q 表示当前位置想寻找什么；
- K 表示每个位置可以如何被匹配；
- V 表示匹配成功后实际取走的信息；
- 因果掩码阻止当前位置读取未来 token 的信息。

### 周末实验，约 4–5 小时

使用 CPU 运行一个只有 4 个 token、单个 attention head 的教学例子。输入和参数可以使用小型固定矩阵，不要求生成有意义的语言。

实验首先打印：

- 输入 `X` 的形状；
- `Q`、`K`、`V` 的形状；
- attention score 的形状；
- softmax 后的注意力权重；
- 最终输出及其形状。

然后完成三个观察任务：

1. 对同一输入分别开启和关闭因果掩码，检查未来位置的权重是否为零。
2. 保持参数不变，只修改第 4 个 token 的输入；开启掩码时，检查前 3 个位置的输出是否保持不变。
3. 将序列长度从 4 改为 8、16、32，记录 attention score 的形状与元素数量。

| 序列长度 | score 形状 | 元素数 |
| ---: | ---: | ---: |
| 4 | 4 × 4 | 16 |
| 8 | 8 × 8 | 64 |
| 16 | 16 × 16 | 256 |
| 32 | 32 × 32 | 1024 |

小规模的单次运行时间不用于得出性能结论。本周只观察计算行为和中间数据规模。

### 第一周复盘

用半页内容回答：

1. Q/K/V 分别参与哪一步计算？
2. 因果掩码限制了什么信息流动？
3. 输入长度加倍时，attention score 的元素数如何变化？
4. 当前看到的哪些部分主要涉及计算，哪些可能涉及数据搬运？
5. 还有哪两个概念没有理解？

## 第 2 周：推理、KV Cache、Agent 与记忆

### 平日短时学习

每天选择一个主题投入 20–30 分钟：

1. 逐 token 生成；
2. prefill 和 decode；
3. KV Cache 的内容及作用；
4. Agent 的模型—工具—状态循环；
5. 短期状态、长期记忆与 KV Cache 的区别。

每次只画一张小型数据流图，并记下一个尚未解决的问题。

### 周末实验，约 5–6 小时

#### 实验一：逐 token 生成与 KV Cache

- 输入一串已有 token 并完成 prefill；
- 每次只加入一个新 token；
- 保存此前 token 的 K/V；
- 对比每一步完整重算与复用 K/V 的输出；
- 记录每一步新增、读取和保留的数据。

#### 实验二：Agent memory 纸面原型

画出以下闭环，暂时不要求实现完整 Agent：

`用户目标 → 读取当前状态 → 模型决定下一步 → 调用工具 → 获得观察 → 更新状态/写入记忆 → 继续或停止`

明确四类对象的边界：

| 对象 | 生命周期 | 主要作用 |
| --- | --- | --- |
| Context | 一次模型调用 | 提供当前输入 |
| KV Cache | 一次生成过程 | 复用历史 token 的 K/V |
| Agent state | 一次任务或工作流 | 保存当前进度和控制状态 |
| Long-term memory | 跨任务、跨会话 | 保存事实、事件、经验和规则 |

## 第 3–8 周细化方向

### 第 3 周：增量 Attention 与 KV Cache

- 用同一组参数分别实现完整重算和增量计算。
- 对齐每一步输出，排除缓存实现造成的数值偏差。
- 记录缓存布局、每步新增容量、读取量和写入量。
- 推导序列长度、层数、KV head 数、head dimension 和数据类型对容量的影响。

### 第 4 周：推理性能

- 分开测量 prefill 和 decode。
- 改变输入长度、输出长度和 batch size。
- 记录 TTFT、每 token 延迟、吞吐和显存占用。
- 将实测数据、公式估算与尚未验证的推测分别标记。

### 第 5 周：最小 Agent

- 定义一个小型、可重复的芯片研发助手任务。
- 实现至少一个只读工具和一个状态更新操作。
- 保存每一步模型输入、模型输出、工具调用、观察结果及停止原因。
- 分清业务状态、模型上下文和程序控制状态。

### 第 6 周：结构化长期记忆

- 分别定义事实、事件和规则的字段。
- 至少包含时间、来源、实体、内容、状态和版本信息。
- 实现写入、读取和跨会话恢复。
- 让回答能够指出所依据的记忆记录。

### 第 7 周：生命周期

- 加入需求更新、旧结论失效、同名实体、来源冲突和定向删除案例。
- 区分当前状态查询与历史状态查询。
- 记录一次逻辑写入引发的索引、版本和摘要更新，观察写放大。
- 检查删除后数据是否仍会进入模型上下文。

### 第 8 周：预研收敛

- 对写入、更新、读取、上下文组装和模型推理分阶段计时。
- 记录 P50/P99、存储访问量、索引规模、写放大和 token 成本。
- 选择一个主导瓶颈，提出可证伪的软硬协同假设。
- 给出质量、性能、能耗及安全/隐私方面的预期收益和反例。

## 时间不足时的取舍

某周只有 5 小时时，按以下顺序安排：

1. 把周末实验跑通；
2. 完成核心视频或阅读；
3. 写半页实验复盘；
4. 延后补充材料和数学推导。

如果有 8 小时，将额外时间用于修改实验、构造反例和解释结果，不以增加课程数量为目标。

## 实验记录约定

- 记录模型、数据、上下文预算、生成参数、随机种子和运行环境。
- 区分实测、公式估算和推测。
- 小样本下报告原始数据，不急于解释尾延迟。
- 每次实验至少留下：研究问题、配置、结果、解释、限制和下一步。
- 每个架构方向都必须转化为可证伪假设，而不是只描述潜在收益。
